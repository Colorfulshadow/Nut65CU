# 相对原厂 NUT65 源码的改动

## p13 开发增量（2026-11-01，协议 6，未测试、未上机）

新增 `cu_debounce.c`：1–30 ms 自定义消抖、正常与游戏独立、八个连接/全局槽、Fn+D 共用写入入口。协议 0x33/0x34 带槽与请求标记回显；设置持久化在旧扩展区 offset36 的预留字节，旧 profile / VIA / 宏与全局 EEPROM 布局不变。SPI Flash 读取范围检查避免 u32 加法回绕。完整开发状态与型号区别见 `firmware/p13/CHANGES.md`；已发布 p12 二进制保持冻结。本轮没有实现 HID / 无线安装器。

起点：[hangshengkeji/qmk_firmware](https://github.com/hangshengkeji/qmk_firmware) @ `3164abd3` 的 `keyboards/leku/nut65`（普通版 NUT65，PID `0xE51A`）。
`keyboards/leku/nut65cu` 由它复制而来；2026-10-31 起两个型号（NUT65 CU 与普通版 `nut65rgb`）的共用代码移到 `keyboards/leku/nut65_shared`（第 7 节）。
对仓库共享代码的修改在 `patches/oem-shared-fixes.patch`。

## 1. 适配 NUT65 CU 硬件

CU 与普通版使用同一套主控和引脚（矩阵、LED 电源 A8、升压 A9、USB 电源 B1、插线检测 A7、满电 A15、音乐 B6/B7），
差别在灯珠：普通版 71 颗键灯 + 80 颗灯带，CU 是 8 颗指示灯 + 80 颗灯带。详见 [hardware.md](hardware.md)。

- `keyboard.json`：名称 `NUT65 CU`，PID `0xE545`；88 颗灯的 rgb_matrix 布局（0–7 指示灯，8–87 灯带从左到右）。
- `config.h`：蓝牙名 `NUT65 CU BT1–3`、2.4G 名 `NUT65 CU 2.4G`（与原厂 CU 固件一致）；灯珠数与各指示灯索引
  （连接 Q/W/E/R/T、Caps 5、电池 6 = 左 Ctrl、Win 锁 7）。
- 原本闪在某个键灯上的提示（亮度 / 速度到头、Win/Mac、消抖、律动校准）改为整条灯带闪烁，使用伪索引 240–246。
- 电量查询（Fn+空格）改为灯带 10 段显示；开机动画沿灯带跑；删除普通版空格灯 / 灯带锚点镜像表。
- 8 颗指示灯每帧先清空，只显示状态，不被灯效染色。
- 启用 bootmagic（按住 Esc 插线 = 清除设置 + 进入刷机模式），作为快捷键失效时的退路。

## 2. 修复原厂代码的问题

| 问题 | 修复 |
|---|---|
| Fn+右Shift+Esc 进刷机前调用 `eeconfig_disable()`，每次刷机都清空设置 | 删除该调用 |
| Fn+D 消抖切换无效（两个分支都用固定 8 ms），且开机时开关含义与切换时相反 | 自定义消抖 `hs_debounce.c` 使用运行时的 `hs_deb`；开机逻辑与切换一致 |
| 两个 5 分钟休眠计时器（`lowpower.c` 与 `wls.c`）同时触发时，残留的休眠请求让键盘唤醒后立刻再睡 | 唤醒时清除残留请求；去掉 `wls.c` 中重复的计时器，VIA 的休眠设置直接写入 `lowpower.c` 的计时器 |
| VIA 休眠选"不休眠"时，`wls.c` 的计时器每个循环都立即触发休眠 | 随上一条一并解决，"不休眠"真正生效 |
| VIA 录灯缓冲读写信任主机给的长度，可越过 32 字节 HID 包 | 长度限制在包内 |
| 无线模块接收帧信任长度字节，可越过接收缓冲区（Raw HID 经 2.4G/蓝牙也走这里） | 超长帧丢弃（共享代码补丁） |
| 插着线但在用无线设备时，USB 上的 Raw HID 请求被回复到无线那边，电脑收不到 | 回复走请求进来的那条路（共享代码补丁，`md_raw.c`） |
| Pixel Fractal 灯效对没有灯的键位写 `NO_LED`（255），越界破坏内存——CU 大部分键位都没有灯 | 跳过 `NO_LED`（共享代码补丁） |
| Fn+N 全键无冲：无论开关都播放同一段红→蓝→绿动画 | 绿闪 = 开，红闪 = 关 |
| 用户数据块初始化不写版本号 | 补写版本号；用 CU 专用版本号识别其他固件留下的设置，首次启动自动恢复出厂一次 |

部分修复参考了 [MoonZhe/Nut65](https://github.com/MoonZhe/Nut65)。

## 3. 灯光调整

- 删除全部 QMK 按键灯效（CU 没有单键灯），只保留原厂的 13 种灯带模式。
  灯带与指示灯在 rgb_matrix 的指示灯钩子里绘制，而该钩子只在有灯效运行时调用，所以底层固定运行一个 Solid Color。
- 亮度键（Fn+↑↓）调灯带亮度 5 档（与 Fn+PgUp/PgDn 相同）；速度键（Fn+←→）调彩虹模式流速。
- 所有整条灯带的显示（提示闪烁、电量、番茄钟、WPM）按灯带亮度限制，最高约 30%：
  80 颗灯同时满亮度白光会让升压电路明显啸叫。

## 4. 新功能（`cu_features.c`）

| 功能 | 说明 |
|---|---|
| 番茄钟 | Fn+; 轻按开始 / 下一阶段，按住 1 秒停止；Fn+' 显示 / 隐藏进度条。工作结束绿闪 6 次并开始休息，休息结束红闪 6 次。计时期间禁止空闲休眠（休眠时 MCU 时钟停止，计时会冻结），电量耗尽时除外 |
| WPM 速度条 | Fn+A 开关；从中间向两端填充，绿→黄→红，满格值可调；峰值标记停留 1.5 秒 |
| 低电量提醒 | 电池供电时 15–30% 每 30 秒黄闪 2 次，< 15% 每 15 秒红闪 4 次 |
| 插线切有线 | 插线切 USB，拔线回到原无线设备；只连充电器（5 秒内无 USB 主机）也会切回；插线时手动选设备则取消。切回目标存 EEPROM，关着电源开关插线使用时，下次电池开机自动切回 |
| VIA 菜单 | Light bar：模式 / 亮度 / 速度；Settings：休眠时间、插线切有线、低电量提醒、番茄钟时长与进度显示、WPM 显示与满格值 |

设置存放在用户数据块末尾 8 字节（`cu_settings_t`）。新增键码 `CU_WPM`、`CU_POMO`、`CU_PSHW`（`0x7E1E`–`0x7E20`），VIA 配置文件补全了所有自定义键名。

## 5. 底层：外部 Flash、日志、计数、每设备设置、模式（2026-10-12）

新文件都在 `keyboards/leku/nut65cu/`：

| 文件 | 功能 |
|---|---|
| `cu_store.c` | 外部 SPI Flash：读 JEDEC ID 得到容量；异步扇区擦除（QMK 的驱动只有阻塞擦除，一次约 50–400 ms）；只写自己的区域。区域里若有不是本固件写的数据就锁定不写，需用 `cu_hid.py format` 清除 |
| `cu_log.c` | 事件日志，16 字节一条的环形缓冲（512 KB 芯片约 2.4 万条）：开机、休眠（空闲 / 被请求 / 没电）、唤醒（原因，以及睡眠中被无线模块唤醒又睡回去的次数）、电量变化、插拔线、充满、切设备、连接状态、模式、主机时间与标记。每条都带电量与连接状态 |
| `cu_keys.c` | 每个键的累计按下次数（只计数，不记顺序）；有新按键时每 5 分钟及休眠前存盘，带 CRC |
| `cu_profile.c` | 每设备设置：USB、蓝牙 1–5、2.4G 各自记住模式、Win/Mac、Win 锁、全键无冲、数字行、灯带模式与亮度；在某设备上改的就存到该设备，切设备时应用对方的。VIA 可关 |
| `cu_mode.c` | Fn+P：正常 → 省电 → 游戏（灯带白 / 绿 / 红闪）。省电：灯带只显示提醒，整帧全黑 0.5 秒后切断灯珠电源 A8 与升压 A9（原固件只在休眠时断电，88 颗灯珠和升压电路平时一直耗电），最多 1 分钟休眠，1 秒无输入后扫描间让 MCU 空闲；游戏：消抖 1 ms，禁用 Win 键（Win 键下指示灯红） |
| `cu_host.c` | Raw HID 命令（首字节 `0xC5`，与 VIA 共存，见 `cu_host.h`）；Fn+I 在当前窗口打出状态报告 |

- EEPROM：灯光录制（CU 无用）从 4 通道减为 3 通道，腾出的 180 字节作为 CU 扩展块（每设备设置、模式）放在用户数据块最前面，
  数据块总大小与之后的所有地址（含 VIA 键位）不变，升级不会恢复出厂。
- MCU 休眠时 SysTick 停止，日志时间为开机后的清醒时间，不含睡眠时长；`cu_hid.py log` 每次读取前写入一条电脑时间作为锚点。
- 共享代码补丁新增：无线模块接收 1–32 字节的 Raw 包（补零）、模块收发计数（`md_diag`，`cu_hid.py diag`）、Raw HID 按来源回复。
- 新增键码 `CU_INFO`（Fn+I，`0x7E21`）、`CU_MODE`（Fn+P，`0x7E22`）；VIA Settings 新增 Devices 页（模式、每设备设置开关）。
- 注意：QMK 的 VIA 以编译日期作为 EEPROM 校验，刷入不同日期编译的固件时 VIA 改键与宏会恢复默认（本固件自己的设置不受影响）。2026-10-29 起改为固定值，见第 6 节。

电脑端 `tools/cu_hid.py`（Windows，纯 Python，无需安装依赖；USB 或 2.4G）：

| 命令 | 作用 |
|---|---|
| `info` | 状态：连接、电量、模式、Flash、计数 |
| `log [--csv f.csv] [--all]` | 读日志（增量缓存），末尾按开机汇总休眠次数、唤醒原因、电量变化 |
| `keys [--svg map.svg] [--csv f.csv]` | 按键计数与热力图 |
| `profile [on|off|set bt1 mode=eco mac=1 ...]` | 每设备设置 |
| `mode [normal|eco|game]` | 查看 / 设置模式 |
| `diag`、`ping`、`echo`、`list` | 无线模块计数、往返延迟、接口列表 |
| `flash-dump f.bin`、`format --yes`、`keys-clear --yes`、`mark N`、`time` | 备份外部 Flash、清除区域、清零计数、写标记 / 时间 |

## 6. 电脑控制灯光、刷机请求（2026-10-14 – 10-29，协议 2–3）

- **USB 链路看门狗**：插线切有线后，如果电脑在 5 秒内没有识别键盘，就重启一次 USB（最多两次），仍不行再退回原来的无线设备。
  （最初是 3 秒；实测 Windows 偶尔要 3–4 秒，3 秒会打断正在进行的识别，2026-11-01 改为 5 秒。）
- **协议 2**：电脑可以临时控制灯带（4 层，常亮 / 呼吸 / 闪烁 / 流动 / 扫描 / 进度）与 Q–T 指示灯，带超时自动熄灭；连上时发 LINK_UP 事件。
- **协议 3**：电脑发起的刷机请求（BOOT_REQUEST）：灯带琥珀色闪烁，**轻按 Esc** 确认进入刷机模式、按其他键取消、10 秒超时；休眠前发 SLEEP 事件。
- VIA 的 EEPROM 校验改为固定值：之后刷入新版本时改键与宏保留（`quantum/via.c` 的补丁）。

## 7. 普通版 NUT65、协议 4（2026-10-31）

- 共用代码移到 `keyboards/leku/nut65_shared/`；新目标 `keyboards/leku/nut65rgb`（普通版，PID `0xE51A`，71 颗键灯 + 80 颗灯带，保留原厂全部逐键灯效）。
  **普通版没有经过真机验证**。
- **协议 4**：INFO 第 1 页报告型号与灯珠数；普通版可由电脑点亮任意键灯（KEY_LIGHT）。
- **修复计时起点下溢**：原来用 `timer_read32() | 1` 表示“非 0 的开始时间”，毫秒数为偶数时它在“将来”，同一毫秒内算经过时间会下溢。
  影响刷机请求的 10 秒等待、插线防抖、USB 看门狗、番茄钟长按判断、延时保存等 10 处，统一改为 `cu_timer_start()`（`cu_timer.h`）。

## 8. 灯带模式 13–24、协议 5（2026-11-01）

灯带在原厂 12 种模式和关闭之外新增 12 种（`nut65_shared/cu_barfx.c`，两个型号共用）：

| 模式 | 说明 |
|---|---|
| 13 星光 | 按下的键在灯带对应位置留下一颗星，闪烁着慢慢熄灭（多为暖白，偶尔淡蓝或金色） |
| 14 涟漪 | 按键处向两侧扩散光波，每次按键换一种颜色 |
| 15 余晖 | 按键处亮起，再慢慢暗回淡淡的彩虹底色 |
| 16 打字热度 | 打字让灯带“升温”：红 → 橙 → 黄 → 白，热量向两侧扩散并冷却 |
| 17 星空 | 深蓝夜空上星星此起彼伏地闪 |
| 18 流星 | 白蓝色的头拖着蓝紫色长尾划过 |
| 19 极光 | 绿、青、蓝紫缓慢起伏 |
| 20 火焰 | 跳动的火苗 |
| 21 海浪 | 蓝色波浪，浪尖泛白 |
| 22 雨滴 | 随机颜色的雨滴出现又淡去 |
| 23 扫描 | 红色光点带拖尾来回扫 |
| 24 隙光 | 铜色到青绿的渐变，一道柔光缓缓穿过 |

- Fn + Backspace 的顺序：原厂 0–11 → 13–24 → 关闭 → 0。环境类跟随 Fn + ← / → 的速度；亮度与原厂模式相同（不会啸叫）。
- 新模式存在本固件设置原来的保留字节里，原厂 EEPROM 布局不变；升级后原来的模式保持不变。
- **协议 5**：INFO 的灯带字节 bit7 = 模式号 bit4；VIA 菜单与每设备设置的灯带模式取值 0–24（`NUT65CU-via.json` 已更新）。
- 文件头署名：本项目写的文件署 Colorfulshadow；在原厂代码上改动的文件保留原版权行并加一行；`keyboard.json` 的 maintainer 改为 Colorfulshadow。
